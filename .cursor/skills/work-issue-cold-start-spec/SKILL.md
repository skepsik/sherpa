# Достаточность постановки

Постановка должна быть самодостаточна для холодного старта: исполнитель не
имеет доступа ни к чему, кроме её текста — ни к переписке, ни к намерениям,
которые не были в неё записаны. Недостаточность прячется в двух разных
формах:

1. **недосказанное** — то, без чего задача невыполнима или опирается на
   данность, которой нет в тексте / пустая отсылка (условные строки ниже);
2. **неполная структура** — базовый блок, без которого постановка нечитаема
   как задача сама по себе (строки «всегда» в той же таблице).

Продуктовые решения живут в **эпике**. Work-issue — чаще голая инженерия.
Если на нарезке всплыл продукт, которого нет в эпике — **эскалация владельцу
сразу** (до кодера). На кодера как на стоп-кран не рассчитывать: просочившийся
продукт чинится переделкой на gate/разборе.

## Дословно vs усмотрение кодера

В постановке **дословно** (или отсылка с тестом «цитата настоящая»):

- уже известное из канона / кода / принятых решений;
- **общие опоры сиблингов эпика**, если они уже решены на нарезке (чтобы не
  переписывать соседние issue; параллельный запуск всё равно ждёт реализации).

Имена модулей/функций/файлов, формулировки текстов, способ тестов и прочий
**безвредный** invent (разный выбор не меняет поведения границы) — на
усмотрение кодера, если задача выполнима. Фиксация наружу в канон —
штатно через «Сверх постановки» → gate (не авария постановки).

**Решающее** поведение не помечать invent: безопасность, доставка, формат
на проводе, поля контракта — если два кодера выберут разное и это видно
пользователю, злоумышленнику или раннеру. Такое — **дословно** (одно
значение) или явный закрытый список допустимых вариантов. Иначе задача
невыполнима / эскалация находки.

## Как отвечать на условные блоки

Ответь да/нет на каждую условную строку таблицы обязательных блоков — целиком,
обязательно, не выборочно. Кода ещё нет — оценивай суждением о
планируемой работе, не механической проверкой. Не додумывай категории
сверх перечисленных в таблице.

При «да» — открой `category-content.md` § с тем же номером и заполни блок
по нему. Проектная специфика — `adapter.md` § с тем же номером.

Постановка вправе вместо дословного текста сослаться на канон —
тест **«цитата настоящая»**: отсылка засчитывается, **только если** фрагмент
по ссылке реально содержит ответ. Что считается «ответом» — своё для каждой
категории, см. `category-content.md`. Общий абзац без деталей — дыра:
пустая ссылка ≠ решение.

Если фрагмент по ссылке ответа не содержит — см. «Эскалация находки» ниже.

## Эскалация находки

На **нарезке** (до кодера), не откладывая на исполнителя:

- всплыло **продуктовое** решение, которого нет в эпике;
- пустая «цитата настоящая» / опора заявлена как известная, а в каноне/коде её нет;
- задача **невыполнима**: не хватает описания поведения/формата настолько, что
  кодер не сможет осмысленно invent'ить;
- решение или опора вне шести категорий — сформулировать находку и вынести
  владельцу.

Не эскалировать только потому, что ещё нет дословного имени API / полей
layout (безвредный invent) — усмотрение кодера + сверх → gate.

## Обязательные блоки задачи

Полная карта блоков постановки, в порядке появления в тексте. Все блоки с
заголовками обязательны. Строки «всегда» содержат контент без исключений.
Условные строки — заголовок присутствует всегда, содержание — только если
триггер в «Когда нужно» сработал, иначе явно «не применимо».

| №   | Блок                              | Когда нужно                                                                                                       | Что содержит                                           |
| --- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
|     | Контекст                          | всегда                                                                                                            | зачем; родитель, если есть                             |
| 1   | Ссылки на канон                   | затрагивает область, которую описывает канон/спецификация проекта                                                 | `category-content.md` § 1                              |
| 2   | Предусловия                       | имеет родителя, blocked-by или смежные задачи, от которых что-то можно унаследовать                               | `category-content.md` § 2                              |
| 3   | Публичный контракт                | вводит/меняет то, на что другие вызывающие или будущие задачи будут опираться как на данность (не вывести заново) | `category-content.md` § 3                              |
| 4   | Wire / persistent layout          | вводит/меняет формат данных, читаемый за пределами текущего запуска.                                              | `category-content.md` § 4                              |
| 5   | Граница процесса / повторный вход | вводит >1 точку входа, которые делят эфемерное состояние между вызовами                                           | `category-content.md` § 5                              |
| 6   | Зависимости                       | вводит новую/меняет версию/features существующей runtime/build-зависимости                                        | `category-content.md` § 6                              |
|     | Критерии готовности               | всегда                                                                                                            | проверяемые утверждения «сделано»                      |
|     | Scope                             | всегда                                                                                                            | граница затронутого, без «заодно»/«на будущее»         |
|     | Вне скоупа                        | всегда                                                                                                            | смежные вещи по имени, которые легко спутать с задачей |

Отсутствие блока со «всегда» — дыра. Немой пропуск условного блока (ни
содержания, ни явного «не применимо») — та же дыра.

Триггер «публичный контракт» — про охват опоры (сиблинги эпика, соседние
пакеты, будущие задачи), не про обязанность заранее назвать все имена.
Формальная видимость в языке сама по себе не тест.

## Red Flags — отговорки, которые не освобождают от чеклиста

| Отговорка                              | Почему не считается                                                                                                                                                                              |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| «Простая задача, тут очевидно»         | Простота реализации не отменяет триггеров категорий — ответь на чеклист явно                                                                                                                     |
| «Тут всего один вызов / одна команда»  | Категория «граница процесса» — про **разделяемое состояние между вызовами**, не про число команд; проверь явно                                                                                   |
| «Канон это и так плюс-минус описывает» | «Плюс-минус» не считается — см. тест «цитата настоящая»                                                                                                                                          |
| «Канон в репо, исполнитель сам найдёт» | Холодный старт не ищет по дереву — нужны конкретные пути/`§` (кат. «ссылки на канон»)                                                                                                            |
| «В эпике / parent уже написано»        | Эпик не подставляется в текст child сам; продуктовые данности — выжимкой в child или ссылкой с цитатой настоящей; инженерия сиблингов — в предусловиях / дословных общих опорах, если уже решены |
| «Достаточно blocked-by / parent id»    | Id связи ≠ готовность: что именно можно считать данным — см. кат. «предусловия»                                                                                                                  |
| «Зависимость и так следует из API»     | Если не следует однозначно — имя и зачем в постановке (кат. «зависимости»)                                                                                                                       |
| «Блока нет в тексте = не применимо»    | Условный блок без содержания и без явного «не применимо» — дыра                                                                                                                                  |
| «Имён ещё нет — эскалируем»            | Нет: invent кодера + сверх → gate, если поведение/охват достаточно описаны и продукт не всплыл                                                                                                   |
| «Формат потом, кодер разберётся»       | Нельзя: постановка должна сделать задачу выполнимой; детали раскладки без заранее известных опор сиблингов — у кодера, но смысл формата — в тексте                                               |

## Граница постановки и усмотрение исполнителя

В постановку — блоки выше и заполненные условные. Не раздувать инвентарём
будущего diff.

Имена и форма, не зафиксированные как «уже известные» / «общая опора
сиблингов», — у кодера. Наружу, чего не было дословно в постановке,
попадёт в «Сверх» и на gate в канон (или «оставили») — штатный путь.

## Расширение списка категорий

Если решение/опора не покрывается ни одной категорией — «Эскалация находки»;
в находке — почему не подходит ни одна. Новая строка в таблице — решение
владельца в том же обсуждении.
