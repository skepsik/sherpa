# Проектные подсказки по категориям

Секции с тем же номером, что в `SKILL.md` / `category-content.md`.
«—» — готовой подсказки нет; ответ суждением по задаче (см. `SKILL.md`).
Категория при этом может триггериться.

## 1. Ссылки на канон

Пути от корня `sherpa` в бэктиках (`docs/…`), не markdown-link и не URL
удалённого wiki. В теле issue относительный `](docs/…)` GitHub резолвит
от `/issues/`.

Канон сейчас: `docs/frames.md`, `docs/concept.md` (и смежные в `docs/`).
Канон-proper дописывается на **gate** (fold из сверх / wire), не кодером
в ходе work и не самовольно на нарезке.

## 2. Предусловия

Сиблинги внутри эпика: общие уже решённые опоры — дословно в постановках,
которым они нужны (стабильность текстов при пачке issues). Пока опора не
реализована — блокер исполнения зависимого issue; выигрыш дословности —
не переписывать тела после гейта предшественника.

## 3. Публичный контракт

Типичный охват: контракт бот↔раннер; порт сессии агентского харнесса;
экспорты `packages/*`; публичные точки входа `packages/bot` /
`packages/runner`, если на них опираются сиблинги эпика.

«Сверх» ловит только **наружу** (кросс-пакетный `export` / runtime-deps).
Внутренние опоры сиблингов туда не попадут — если они уже решены на
нарезке, писать дословно в постановке; иначе invent локально и при нужде
править сиблингов после гейта / переделкой.

## 4. Wire / persistent layout

Протокол бот↔раннер, схема БД реестра/прав, формат stream событий
харнесса наружу — если задача вводит или меняет формат за пределами
текущего запуска. Смысл формата — в постановке; конкретная раскладка —
по правилу «известно / сиблинги / иначе кодер».

## 5. Граница процесса / повторный вход

Сессия агента (`resume`), блокировка цели записи, reconnect раннера к
боту, очередь сообщений топика — типичные триггеры.
