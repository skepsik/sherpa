# Содержание по категориям

Секции пронумерованы как строки чек-листа в `SKILL.md`. Применять нужно
только те, где вышло «да» — остальные не относятся к текущей постановке.

## 1. Ссылки на канон

Конкретные пути/§ канона/спецификации, которые касаются этой задачи.

## 2. Предусловия

Конкретная готовность соседних/зависимых задач: что именно уже сделано и можно считать данностью, не только формальная связь «блокируется задачей N».

## 3. Публичный контракт

Охват — см. `SKILL.md` (абзац у триггера): опора для сиблингов эпика /
соседей / будущих задач; формальная видимость в языке сама по себе не тест.

В постановке:

- **поведение / смысл опоры** — достаточно, чтобы задача была выполнима
  (критерии или отдельный подпункт);
- **имя / сигнатура дословно** — только если уже известно (канон, код,
  принятое решение) **или** это общая опора сиблингов эпика, уже решённая
  на нарезке;
- иначе — явно, что конкретные имена на усмотрение кодера; фиксация наружу
  пойдёт через «Сверх» → gate → канон (штатно).

Если на границе отдаётся ошибка наружу — описать **канал** и ожидаемую
семантику отказа; конкретные имена error-типов — по тому же правилу
(известны / общие для сиблингов → дословно; иначе кодер).

Развилки, когда охват сработал:

1. под охват не должно попадать — явно вне блока (внутренняя деталь этой задачи);
2. уже известно — дословно или отсылка с тестом «цитата настоящая»;
3. ещё не решено, инженерия — усмотрение кодера + сверх; не эскалировать
   только из‑за отсутствия имени;
4. всплыл **продукт**, которого нет в эпике — эскалация на нарезке
   (`SKILL.md` § «Эскалация находки»).

## 4. Wire / persistent layout

Постановка должна описать **новый формат достаточно**, чтобы задача была
выполнима (что хранится/передаётся, зачем, границы читаемости).

Дословная раскладка (поля, порядок, длины, magic) — только если уже
известна из канона/кода **или** это общая опора сиблингов, решённая на
нарезке. Иначе — усмотрение кодера; на gate сверить с постановкой и при
нужде fold в канон.

Отсылка на раздел канона, где раскладки нет — дыра «цитаты настоящей»
только если постановка **утверждает**, что раскладка уже там. Если
раскладка ещё invent — не ссылаться как на готовое.

## 5. Граница процесса / повторный вход

Обязательные слоты:

| Слот                        | Вопрос                                                                                       |
| --------------------------- | -------------------------------------------------------------------------------------------- |
| persist-between-invocations | Что переживает границу процесса/вызова (файл, env, ничего)                                   |
| re-entry                    | Как войти в уже развёрнутое состояние: шаги/API, отличные от cold start                      |
| re-entry-forbidden          | Что запрещено делать при повторном входе (например не пересоздавать поверх живого состояния) |

Различай два случая до применения слотов:

- **один процесс**, несколько вызовов к одному живому состоянию — cold start
  и повторный вызов действительно разные пути; слоты нужны.
- **разные процессы** (отдельный запуск на каждый вызов) — состояния
  первого вызова для второго не существует; молчание постановки часто
  провоцирует выдуманный persist — дыра.

Отсылка «см. канон» без слотов — дыра. Непокрытое (конкурентный доступ,
протухание сессии, recovery после аварии) — не додумывать слоты заранее;
при нужде — эскалация находки на нарезке.

## 6. Зависимости

В постановке дословно:

- имя зависимости, версия/источник;
- зачем именно она нужна, если не следует однозначно из уже названного
  контракта/канона.
