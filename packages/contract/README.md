# @sherpa/contract

Контракт границы транспорт ↔ раннер: типы и схемы протокола между `packages/bot` и `packages/runner`.

## Границы ответственности

- **Фильтр отправителя.** Рамки: один пользователь, ввод из своего Telegram. Отсечь чужие апдейты — обязанность транспорта (`packages/bot`). В inbound нет идентификатора отправителя: раннер события от «своих» и «чужих» не различит.
- **`answerCallbackQuery`.** Id callback-запроса Telegram на провод не выносится. Бот отвечает на callback локально; на раннер уходит только `question_answer` с `requestId` / `data` / `place`.
- **Доставка inbound.** Канал отдаёт envelope **at-most-once**: один send без ack. Обрыв / полумёртвый сокет — heartbeat. Нет клиента — кадр не буферизуется. Кадр, уже ушедший в мёртвый сокет, не переигрывается. `eventId` стабилен для одного Update (Telegram: строка `update_id`); после рестарта транспорта тот же `eventId` может уйти по каналу снова.
- **Длина текста (контракт).** Текст команд/сообщений на проводе (`send_message` / `send_question` / `resolve_question` и inbound `message`) ≤ **4096** символов. Раннер обязан укладываться; транспорт при нарушении своего лимита после упаковки — `transport_rejected`.
- **Кнопки (контракт).** Для **каждой** кнопки: байты UTF-8 `requestId` + байты UTF-8 **её** `data` ≤ **48**. Раннер считает по полям контракта, без знания упаковки транспорта. В `requestId` / `data` не класть символы, требующие JSON-экранирования в упаковке транспорта: без `\`, `"`, управляющих. Запас до лимита callback transport — зона бота; превышение после упаковки → `transport_rejected`.
- **`Place`.** Непрозрачный id места: непустая строка **без whitespace**. Топология мессенджера и кодек id — зона транспорта; раннер строку не разбирает. Старая структурная форма (`kind` / `chatId` / …) на проводе не принимается.
- **Порядок команд в `Place`.** Лента = история: порядок сообщений в месте обязателен. Бот исполняет outbound-команды **одного** `Place` строго по очереди (следующий `execute` — после завершения предыдущего, успех или отказ); разные `Place` могут идти параллельно. Раннер при `unknown` (таймаут / обрыв) освобождает очередь ожидания `Place` и **не** молча ретраит; следующую outbound в тот же `Place` может отправить сразу. Порядок эффектов в мессенджере обеспечивает сериализация на боте: если после таймаута ушла вторая, а первая ещё исполняется — в ленту уходит сначала эффект первой, потом второй.
- **Соответствие исхода команде.** Декодер не связывает тип команды с типом результата. Раннер **обязан** сверять исход с ожидаемым типом команды по `id` корреляции; иначе расхождение будет тихим.

## Inbound (транспорт → раннер)

`encodeInbound(eventId, event)` / `tryDecodeInbound` → `{ eventId, event }`.

`place` — opaque строка. Парные `type`:

| Inbound           | Смысл                                                         |
| ----------------- | ------------------------------------------------------------- |
| `message`         | текст пользователя в `Place`; опционально `delivery`          |
| `question_answer` | ответ на вопрос: `requestId` / `data` / `Place`               |
| `session_break`   | явный break текущего хода: только `place` (без текста задачи) |

`message.delivery` (опционально): `interject` \| `after`. Нет поля — дефолт mid-run на стороне раннера (не на проводе). Невалидное значение → кадр не принимается.

## Outbound (раннер → транспорт)

`encodeOutbound` / `tryDecodeOutbound` — команды:

| Outbound           | Смысл                                                                      |
| ------------------ | -------------------------------------------------------------------------- |
| `send_message`     | текст в `Place`                                                            |
| `send_question`    | вопрос + непустые кнопки + `requestId`                                     |
| `resolve_question` | фиксация выбора на `messageId` (текст; кнопки снять); единственный edit    |
| `set_status`       | `Place` + `status`: `busy` \| `idle` (исполнение на транспорте — заглушка) |
| `create_place`     | создать место: `place` родителя + `title`                                  |

Исходы — `encodeOutboundResult` / `tryDecodeOutboundResult`:

| Исход             | Когда                                                    | Поля                                         |
| ----------------- | -------------------------------------------------------- | -------------------------------------------- |
| `send_ok`         | успех `send_message` / `resolve_question` / `set_status` | `commandType`; **без** `messageId`           |
| `question_ok`     | успех `send_question`                                    | `commandType: 'send_question'` + `messageId` |
| `create_place_ok` | успех `create_place`                                     | `place` (opaque id нового места)             |
| `error`           | отказ                                                    | `commandType` и непустой `message`; код      |

Коды `error`: `place_unavailable` | `place_create_failed` | `send_failed` | `transport_rejected`.

Envelope: `v` / `direction` / `id` + `command` или `result` (inbound: ещё `eventId`). `WIRE_VERSION` = **1** (отсутствие `delivery` = дефолт раннера — без bump).
